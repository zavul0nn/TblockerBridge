# Security

Не публикуйте в issues пароли, приватные ключи, webhook URL/headers, полные пользовательские access.log и неочищенные системные конфиги.

Для отчёта обычно достаточно версии ОС/Python, версии TblockerBridge, состояния unit, обезличенного сообщения ошибки и указания схемы HAProxy (host/bridge).

Для приватного сообщения об уязвимости используйте GitHub **Security → Report a vulnerability**, если владелец репозитория включил private vulnerability reporting. До включения этого канала свяжитесь с владельцем приватно; чувствительные детали в публичный issue не отправляйте.

Ключ экспортёра даёт чтение списка активных IP/сроков, а не административный доступ. Не используйте для рабочего соединения административный ключ. Host key проверяйте по независимому источнику. CAP_NET_ADMIN на входе имеет полномочия на весь сетевой namespace; учитывайте это при оценке модели угроз.
