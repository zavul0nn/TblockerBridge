# Подготовка релиза

1. Запустить unit-тесты на Python 3.10+, compileall и bash -n. В Linux выполнить сетевые тесты через `unshare --net`.
2. На отдельной чистой Ubuntu/Debian проверить интерактивный сценарий пары серверов: пароль/ключ SSH, проверка fingerprint, отсутствующий JSON, появление первой блокировки, штатный TTL, повторный install, update и uninstall. Для этого не использовать рабочую ноду с пользователями.
3. Проверить policy-rc.d и enabled-state nftables.service до/после установки зависимостей. В отдельной тестовой VM проверить отказ apt и откат policy.
4. Повторить с существующим Docker-контейнером и исходными UFW-правилами: PID/start times, IDs контейнеров и структурный ruleset не должны измениться за исключением собственной таблицы.
5. Проверить URL https://github.com/zavul0nn/TblockerBridge в README. Включить private vulnerability reporting, если планируется этот канал SECURITY.md.
6. Выполнить `python3 build_release.py`: архивы и SHA256SUMS появятся в dist/. Сборка использует allowlist и не включает .git, кеши, ключи и журналы.
7. Создать тег/релиз и приложить два архива и SHA256SUMS. Публикация и push выполняются после выбора репозитория владельцем.

До завершения smoke-теста на чистой ОС не заявлять, что универсальная установка проверена целиком. Полный сетевой тест исходного решения и unit-тесты установщика проверяют другие уровни.
