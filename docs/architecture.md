# Архитектура и границы

TblockerBridge — pull-синхронизатор. Решение о нарушении принимает существующий tblocker. Источником истины служит его сохранённая карта; повторного анализа Xray access.log нет.

## Данные

Входной формат upstream:

```json
{"198.51.100.20":{"ip":"198.51.100.20","username":"example","blocked_until":"2026-10-28T10:00:00.123456789Z"}}
```

Это пример структуры; TEST-NET-адреса в рабочем режиме не блокируются. Экспортёр отбрасывает username и передаёт строки JSON:

```json
{"version":1,"generated":1234567890.0,"blocks":{"8.8.8.8":1234567990.0}}
```

Все сроки абсолютные, в Unix seconds. RFC3339Nano исходного JSON читается с часовым поясом. Количество записей ограничено 10000, размер снимка — 2 МиБ. Неизвестная версия протокола, duplicate JSON keys, неправильные IP, неопределённые/бесконечные сроки и рассогласование часов отвергаются.

## Чтение неатомарного файла

Upstream записывает JSON через os.WriteFile. Выполняются два одинаковых чтения с интервалом 30 мс и разбор структуры. Несогласованное чтение не отправляется. Отсутствующий файл при существующем каталоге — нормальное пустое состояние свежей ноды. Отсутствующий каталог, dangling symlink, ошибка доступа и испорченный JSON не превращаются в пустой список.

Это зеркало сохранённого состояния: если исходный блокер не смог записать JSON, синхронизатор не может узнать его внутреннее состояние. Неизменённая upstream-семантика остаётся такой: повторное обнаружение активного IP обычно не продлевает срок; изменение уже сохранённого срока зеркало поддерживает.

## Firewall

HAProxy host listener принимает реальные клиентские пакеты в input. Цепочка с приоритетом -20 выполняется раньше обычного filter 0; DROP окончателен. Она не зависит от conntrack state и останавливает также established traffic на выбранный TCP dport.

Набор целиком заменяется в одной транзакции nft -f. Timeout для каждого элемента = blocked_until − now; повторная запись не продлевает фактический срок. Сверка выполняется при изменении снимка и периодически каждые 10 секунд. Если собственная таблица отсутствует, она воссоздаётся. Ручное изменение структуры существующей таблицы не поддерживается.

После успешной nft-транзакции BanEnforcer вызывает `ss -K` для серверных TCP-сокетов: локальный sport входного порта + точный dst IP клиента, включая IPv4-mapped представление. Слушающие сокеты и minisockets TIME_WAIT/SYN_RECV исключены. Это именно уничтожение TCP-сокета через SOCK_DESTROY, а не удаление записи conntrack. HAProxy получает завершение клиентской стороны и обрабатывает свою соответствующую backend-сессию.

Результат закрытия проверяется повторным запросом ss: успешный exit code сам по себе не доказывает поддержку ядром. При ошибке блокировка остаётся и попытка повторяется; журнал ошибок ограничен по частоте. Обработка очереди закрытий ограничена по времени между попытками. Один вызов ss имеет timeout 3 секунды. Повторные неизменные снимки не закрывают уже обработанные адреса заново; после истечения старой блокировки новая блокировка того же IP снова закрывает сокеты. При рестарте проверяются активные адреса восстановленного состояния. Настройка close_connections=false отключает только дополнительное закрытие.

Удаление conntrack и обращение к runtime API HAProxy не выполняются. Блокировка исходного IP в output, массовый сброс backend-соединений и изменения Docker forwarding отсутствуют. Docker bridge/NAT требует иной схемы и отклоняется preflight-проверкой.

## Перезапуск и обрыв связи

На входе кеш хранит абсолютные сроки. Сначала восстанавливается его неистёкший остаток, затем полная карта источника. При обрыве соединения зеркало переподключается. Истёкшие элементы удаляются ядром независимо от процесса. Ошибка чтения не вызывает снятие всех банов.

Если JSON исчезнет при работающей исходной службе и доступном StorageDir, источник сообщит пустое состояние. Это выбранная семантика отсутствующего файла; она поддерживает свежую ноду и отражает отсутствие сохранённых блокировок.

## Права

Административный SSH используется только установщиком. Рабочая служба использует другой ключ. На источнике принудительная команда и ограничения ключа не позволяют произвольный shell. У каждого входного сервера отдельный source account/ID; удаление одного не трогает остальных.

CAP_NET_ADMIN на входе шире доступа к одной nft-таблице. Код root-owned, NoNewPrivileges и ограничения systemd уменьшают поверхность атаки, но скомпрометированный процесс с этой capability потенциально может менять другие сетевые параметры в своём namespace. Отдельного привилегированного RPC-демона в версии 1.0 нет.

## Установка как транзакция

Preflight → зависимости без рестартов → резервные снимки → собственные marker-файлы → отдельные аккаунты/ключ → проверка ограниченного SSH → собственный unit → проверка свежего источника.

Откат удаляет только принадлежащие instance объекты. Чужие каталоги, пользователи и nft-таблица с занятым именем не перезаписываются. Глобальный ruleset не восстанавливается. Зависимости и снимки сохраняются; неустранимый сетевой отказ при удалённом откате явно сообщается с ID.

Установка рассчитана на обычное успешное завершение процесса и обработанные исключения. SIGKILL или отключение питания могут оставить частично установленный marker. В таком случае нужны проверка журнала и ручная очистка принадлежащих ID объектов; установщик не должен угадывать принадлежность чужих файлов.
